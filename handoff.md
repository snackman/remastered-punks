**dynamic and soulbound** — the remastered token follows the original punk via on-chain
`punkIndexToAddress` lookup; transfers/approvals are blocked (EIP-5192).

The **stacking compositor** (`lib/stack-compositor.js`) is now the canonical render path,
replacing the older per-punk modification model. Every human female composites on ONE
remastered base (ear shifted down 1px) + raw/edited trait sprites. `stackPunk` is wired
through `api/[punkId].js`, the traits page, and the compare page. Eligibility is defined
as: a punk is eligible iff the old (unremastered) composite differs from `stackPunk`.

## Contract design tradeoffs (intentional, not bugs)
1. **No automatic `Transfer` event on secondary CryptoPunk sales** — `ownerOf` is always
   correct (live lookup); log indexers lag until someone calls `syncOwnership` (we can
   poke it from a bot/subgraph watcher, or the new owner can).
2. **`balanceOf` always returns 0** — documented; use an indexer for counts.
3. **`merkleRoot` is immutable** — eligibility frozen at deploy (verified final: 3,434).
